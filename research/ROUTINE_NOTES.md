Good sources: data.ny.gov MTA hourly API (aggregatable with SoQL), SEC EDGAR full-text of Energy Monster filings, INFORICH securities report on edinetdb. Whenever a value changes here, update params.js with the same value, range, confidence and URL, then run `node simulator/cli.mjs 50 normal all` and record rentals/station/day vs the 0.5–3 benchmark band in the daily report.

- 2026-11-08: api.census.gov now 302-redirects keyless calls; Census Reporter's API (api.censusreporter.org/1.0/data/show/latest?table_ids=…&geo_ids=…) serves the same ACS numbers without a key. USNO's rstt API works for sun times (timeanddate.com 403s). CTA publishes only daily station entries; WeGo and Miami-Dade publish no open hourly ridership.
- 2026-11-08: Re-run any API-based number yourself (MTA, CTA, ACS) rather than sending it to the verifier — it takes one curl and frees the verifier for HTML/PDF claims. The verifier could extract PDFs with pypdf when the fetch tool couldn't; agents without that should say "PDF not extractable" rather than quote snippets.
- 2026-11-08: p_aware and p_low_peak are calibrated jointly (only their product is pinned by the 0.5–3 rentals/station/day band). Before changing either, run a sweep and report profit at each value instead of silently moving the default.

- 2026-11-09: data.ny.gov has MTA Subway Origin-Destination estimates (2023 uhf3-t34z, 2024 jsu2-fbtj, 2025 y2qv-fytt, 2026+ 28vm-gjqr; station complex ids in 39hk-dx4f). It gives exits, which the hourly-entries dataset lacks — use it for any station profile. Miami-Dade monthly ridership PDFs live at miamidade.gov/resources/transportation_publicworks/documents/rtr/YYYY-MM-monthly-ridership-report.pdf (≈3-month lag).
- 2026-11-09: pypdf is installed at ~/Library/Python/3.12/lib/python/site-packages but `python3 -I` hides user site-packages; append that path to sys.path inside the script. Tell agents this up front — today one agent couldn't extract PDFs because of it.
- 2026-11-09: Before any calibrated parameter debate, check identifiability with the simulator itself (CRN runs reaching the same product two ways). It took 11 s and settled queue item 2. Re-run research/scripts/calibrate_conversion.mjs after any footfall/profile change.

- 2026-11-10: Run Morris screening (`research/scripts/morris_screening.mjs`, ~150 s) after any engine change. It is a cheap bug detector: today it flagged packs_per_kiosk as the #2 profit lever, which traced to failed returns being billed and forfeited. A factor that should hurt profit but helps it is a red flag.
- 2026-11-10: Operator decks beat press releases. INFORICH's TDnet results PDFs (www2.jpx.co.jp/disc/93380/…) contained a real duration histogram that contradicted the company's own press-release line (">60% of users within 1 h"). Search TDnet/EDINET decks for 利用時間 before trusting a PR sentence. Always ask the verifier "what exactly does it measure (users vs rentals, period)".
- 2026-11-10: No paper publishes hourly <20% battery share; stop searching literature for it. Open datasets (ExtraSensory, GreenHub on Kaggle — API download works without login) are the path. Brief an agent to compute it, not to find it.

- 2026-11-11: "Compute, don't search" worked: ExtraSensory zip downloads without login and a stdlib script gives the hourly <20% curve in ~10 s. Condition on **unplugged** time — the unconditional share is dominated by phones on chargers at night. Re-running the agent's script yourself is the fastest verification for computed numbers.
- 2026-11-11: data.ny.gov `5wq4-mkjj` aggregations over a full year × 5 stations (and even 10 weeks grouped by day-of-week) time out (>3 min, no bytes). Query one station × ≤6 weeks at a time, as on 2026-11-08, or use the OD dataset.
- 2026-11-11: Operator multi-market decks give per-station rates in markets closer to the US than Japan: ChargeSPOT Australia (≈US$7–8/rental) runs 0.5–0.8 rentals/station/day. Look for same-operator, price-matched markets before transferring a benchmark. INFORICH delisted (Jun 2026): FY2025 deck + Q1-2026 tanshin are the last.

- 2026-11-12: The system python3 here has no CA bundle (urllib → CERTIFICATE_VERIFY_FAILED). In stdlib scripts that fetch APIs, call `curl` via subprocess instead of urllib. data.ny.gov 5wq4-mkjj answers one-station × one-month daily-total queries in ~3 s each (60 queries ≈ 3 min), so a full year per station is feasible that way.
- 2026-11-12: BLS bls.gov HTML pages block automated fetches; the BLS public API v2 (POST api.bls.gov/publicAPI/v2/timeseries/data/, no key) works. OEWS series = OEUM00 + 7-digit area (0035620 NY, 0034980 Nashville) + 000000 + SOC (6 digits, no dash) + datatype (03 mean hourly, 08 median hourly).

Stop searching for them; the price-matched ChargeSPOT Australia deck stays the best benchmark until Charj pilot data exists.
