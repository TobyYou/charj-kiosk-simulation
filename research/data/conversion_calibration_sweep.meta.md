# conversion_calibration_sweep.csv

- **What:** simulator output (not external data). Rentals/station/day and profit/week for the 13-station network, normal week, 30 Monte Carlo reps per point with common random numbers, as the funnel product c = p_aware × p_low_peak × p_seek is swept.
- **Produced by:** `node research/scripts/calibrate_conversion.mjs 30`, refreshed 2026-11-11 after the rebalancing-fill and forfeit-cost engine fixes, the ExtraSensory LOW_BATTERY_CURVE (weekday + weekend) and phone_rate_fast 1.5: default c → 2.922/day, $416/wk; band upper edge 3.0 now at c ≈ 3.7e-4; ChargeSPOT Australia's 0.48–0.84/day (P074) maps to c ≈ 6e-5 – 1.0e-4 and $0–100/wk. Previous refresh 2026-11-10 after (a) the grace-policy fix for failed returns and (b) per-station MTA OD weekday/weekend profiles. Default c now gives 2.798/day and $471/wk (2026-11-09: 2.82/day, $492/wk). History: a 2026-11-08 run on the pre-OD profile gave 2.927/day.
- **Columns:** c (renters per passer-by at evening peak), rentals_per_station_day, its 95% CI half-width, profit_per_week (USD), its 95% CI half-width, unmet_empty (would-be renters who found an empty station, per week).
- **Identification check (same run):** reaching c = 1.8e-4, 3.6e-4, 7.2e-4 via p_aware or via p_low_peak gave identical outputs (2026-11-10: 1.471 / 2.798 / 5.163; 2026-11-09: 1.494 / 2.815 / 5.175 rentals/station/day). The data can only pin down c, not its factors.
- **Caveat:** re-run whenever footfall profiles, LOW_BATTERY_CURVE, pricing, or stocking change; the c↔rentals map shifts with them.
